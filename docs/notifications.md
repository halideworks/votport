# Workplace notifications

Platform administrators connect Slack, Microsoft Teams, Google Chat and Discord in **System > Notifications**. Each service has its own saved connection, test and disconnect controls. The webhook URLs stay private after saving. A blank URL field preserves the saved connection; Disconnect explicitly disables it. Use environment removes the saved override and returns to the corresponding `VOTPORT_NOTIFY_*_URL` setting.

Connections apply across tenants. Enable notifications on a receive request or delivery link to send its transfer events. Upload completion follows verified publication; failed uploads report rejected sessions and interrupted sessions that received bytes. Delivery notifications report the first download start and recipient acknowledgement. The service test uses only that saved connection. Test all services also includes configured JSON webhook, ntfy, Pushover and email channels.

- [Slack](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks/): create an incoming webhook, choose its channel and paste the URL. Messages use plain text blocks with link previews disabled.
- [Microsoft Teams](https://learn.microsoft.com/en-us/microsoftteams/platform/webhooks-and-connectors/how-to/add-incoming-webhook): create a Workflows webhook for the destination channel and select the Anyone trigger authentication option. Votport sends Adaptive Cards. Give the workflow a co-owner so it can survive changes to its owner's account.
- [Google Chat](https://developers.google.com/workspace/chat/quickstart/webhooks): create a webhook in the space's Apps & integrations settings. Your Workspace administrator may need to enable incoming webhooks.
- [Discord](https://docs.discord.com/developers/resources/webhook): create a webhook under the channel's Integrations settings. Votport disables mentions and embeds and requests server confirmation. An existing `thread_id` query parameter is preserved.

Delivery is best effort. HTTP channels start concurrently, share a 15-second request timeout, and run alongside email outside transfer completion. Messages are bounded to fit service limits. A failed or throttled channel does not prevent another channel from receiving its message. No automatic message retry queue is provided. A successful test means the endpoint accepted the request; verify that the message appeared in the intended channel. Redirects are rejected, and secret URLs and response bodies are never included in notification error logs.

The settings API exposes `notify_slack_set`, `notify_teams_set`, `notify_google_chat_set` and `notify_discord_set`, plus each setting's `_source`. It never returns those URLs. `PUT /api/admin/settings` accepts the corresponding `notify_*` key: a URL saves it, an empty string disables it, and `null` removes the override. `POST /api/admin/notifications/test?channel=slack` tests one saved connection; the other accepted channel names are `teams`, `google_chat` and `discord`. Both mutations require a platform administrator session and `X-Votport: 1`.
