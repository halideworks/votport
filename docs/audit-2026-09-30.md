# Full application audit, 2026-09-30

This audit starts at `0bb6644f75290bc29f5eb917e70d5925e3ea3a76` and covers the
application repository. The earlier [delivery audit](audit-2026-09-29.md)
covered delivery preparation and notification layout; it was not a full source
audit. This report records the subsequent production source audit and fixes. It
does not combine counts from the older 573-item historical ledger.

traced across authentication, filesystem, network, and concurrency boundaries.
Embedded tests were sampled during source review and the complete runnable

from the host.

## Corrected defect groups

The following 34 groups describe concrete defects and the final changes.
Grouping is for readability, not a count of every changed branch or test.

| # | Defect | Change |
| --- | --- | --- |
| 1 | Manual download redirects could forward account credentials to another origin. | Require same-origin 307/308 redirects before following them. |
| 2 | Native administrative calls and stalled download reads could wait indefinitely. | Apply bounded metadata/whole-request and streaming read timeouts at shared client construction. |
| 3 | Summed delivery sizes could overflow. | Use checked aggregation in receive, native fetch, disk checks, and preview. |
| 4 | Old account responses or unauthorized errors could overwrite or erase a newer login. | Compare the complete prior account record under a stable OS lock before replacement or removal. |
| 5 | Browser sign-in could race local removal and recreate erased state. | Retain a cancellable state lease through sign-in and final account replacement. |
| 6 | Local erasure could race device creation and active journal writes. | Hold shared OS state leases outside the removable directory; removal requires exclusive ownership. |
| 7 | Evidence retries could recreate an erased outbox. | Retain state ownership across the bounded network attempt and final evidence write. |
| 8 | Concurrent resume/forget operations could take over another transfer, and uncoordinated lock cleanup could split ownership. | Hold per-entry OS locks through settlement and serialize lock opening and orphan cleanup with a stable registry lock. |
| 9 | Cross-process watch updates could lose list changes or race local erasure. | Serialize watch-list writes and retain state ownership through scan/flight settlement. |
| 10 | Native asynchronous account/workflow callbacks could display or write a previous account's results. | Invalidate generations when account changes begin; discard stale data and errors while retaining completion cleanup. |
| 11 | Failed journal admission could leave native cards running; watch replacement could destroy the previous retry before obtaining a new claim. | Emit failed callbacks on preflight errors, preserve refused resume metadata, and claim the replacement before forgetting the previous session. |
| 12 | Cancelling a resume folder picker discarded the entered password. | Clear passwords only after a destination is confirmed. |
| 13 | Default OIDC subjects differing by case or issuer could share authority; large cookies could fail silently. | Encode exact subject bytes with an issuer namespace, share canonicalization with SCIM, use compact cookies, and report the 4096-byte cookie limit. |
| 14 | Legacy ambiguous subjects and principal purge races could preserve incorrect authority or remove active memberships. | Quarantine old subjects on the initial cutover and every issuer change, revoke old credentials/tokens, invalidate old cookies, and purge memberships only after an actual blocked-principal deletion. |
| 15 | Concurrent automation-token creation could exceed the tenant cap. | Enforce the live-token limit atomically in the insertion statement. |
| 16 | Signed route deadline arithmetic could overflow. | Saturate expiry and skew arithmetic. |
| 17 | Native uploads could continue or publish after request closure/expiry. | Check before admission, cache successful per-write checks for at most one second, cancel on closure, and force a fresh authorization check at publication. |
| 18 | Native downloads could continue after revocation; cancellation during final admission could be missed; HTTP could emit a prepared first frame after revocation. | Add upstream ongoing serve access checks, create the app gate before transactional admission, and check HTTP gates before prepared and queued frames. |
| 19 | Workflow cancellation, recipient removal, or policy changes could leave live streams authorized. | Cancel affected streams after committed changes and check current workflow policy during grant admission. |
| 20 | Unrelated tenants serialized Library mutations and upload allocation. | Retain independent tenant guards through validation and commit, with ownership-safe registry pruning. |
| 21 | Stored claim checks performed repeated queries and quadratic identity matching. | Use one candidate-filtered query and hashed per-name identity sets. |
| 22 | Catalog source metadata I/O ran under the global catalog lock. | Perform source checks before entering the shared publication/cache critical section. |
| 23 | Restore surveys could tombstone records without trustworthy backing storage or scan without bounds. | Retain the qualified directory through the scan and recheck its mount identity; cap records/entries at 100,000 and depth at 128; incomplete surveys retain all records. |
| 24 | S3 HTTP loopback validation rejected bracketed IPv6 loopback. | Accept `[::1]` while still requiring TLS for remote IPv6 endpoints. |
| 25 | Short/empty browser file slices could produce incorrect hashes or loops that never advance. | Require each hash/proof read to return its exact expected length. |
| 26 | Overlapping modal actions shared one answer and replaced each other's content. | Queue the existing modal and resolve each request separately. |
| 27 | Request pagination discarded earlier choices; upload replacement could leave history stale. | Append/deduplicate older requests and use a stable hashed session ID for refresh, including same-second replacements. |
| 28 | Corrupt or blocked session storage could break workflow creation and lose retry identity. | Validate saved drafts, tolerate storage failures, and retain pending operation IDs in memory. |
| 29 | Delivery preparation's progress fill lacked its CSS class. | Attach the existing fill class and check actual browser geometry. Notification button spacing was fixed in the preceding delivery release and remains covered by browser geometry checks. |
| 30 | Failed fencing or partial promotion could start two writers; unreachable replica state could bypass freshness checks. | Refuse promotion after failed fencing, require stopping a partially promoted writer before rollback, and require an explicit topology with fresh replica admission. |
| 31 | macOS shell changes lacked compilation in ordinary CI; publication could precede exact-main CI. | Add a macOS build job, run CI for every main push, and require successful CI for the exact release commit before publication. |

| 33 | WebKit file writers could save a full backing buffer instead of the requested file slice. | Copy only sliced chunks to exact-sized buffers in the shared individual/batch write path. |

## Validation

Local validation includes formatting and deny-warning Clippy for both Rust
workspaces, complete server/client tests, the separate low-file-descriptor
regression, 84 named JavaScript tests with zero failures or skips, ESLint,
design-token generation, the release admission unit test, and dependency policy
checks. Client validation passes 185 tests, including 136 core tests and the
real HTTP/native resume integrations. Server validation passes 970 tests: 906
library, five binary, 55 HTTP, three environment, and one separately executed
low-file-descriptor regression. CI executes two macOS callback ownership
regressions. Browser fixture signals have bounded waits and active-transfer
fixtures include the stable identity required by the status API.

All nine Chromium browser suites pass. The main browser suite also passes in
Firefox and WebKit. WebKit uses an isolated persistent profile for OPFS and
byte-equivalent request bodies during fault injection, because its interceptor
omits Blob bodies. A separate direct Blob transfer verifies all 17 original
payloads on disk. Actual browser checks include modal overlap, progress fill
geometry, notification spacing, paged request retention, transfer cancellation,
workflows, exact batch file contents, and trade. Real generated WASM is used in
browser and JavaScript validation.

Real MinIO acceptance verifies configured S3 credentials, literal keys,
conditional source identities, completion failure withholding URLs, idempotent
retry, backup inventory, and restore. Shared and replica restart drills
restore byte-identical payloads after interruption. The first merged main CI
failed a notification fixture count that included legitimate replacement-
editor requests. Investigation also identified the overlapping shared-cache
failure, reproduced by a deterministic regression. Both were corrected before
deployment or publication. The failed `v0.1.3` tag was retained; the corrected
release is `v0.1.4`.

CI provides native platform builds, NFSv4 acceptance, image identity, and the
complete browser/S3/restart gates.

Seven manually applied mutants fail their targeted tests: moving the native
fetch gate after transactional admission, removing native per-write request
validation, removing the saved restore qualification requirement, and
restoring the old once-per-issuer behavior in an A-to-B-to-A issuer switch.
Removing exact-sized write views also fails the download boundary regression.
Removing the final restore mount check fails the mount-transition regression.
Removing notification cache request ownership fails the overlapping refresh
regression. Failures are assertion failures, not compilation failures or hung
tests. The unmutated source is restored before final gates.

## Performance and remaining operational limits

The [delivery measurements](audit-2026-09-29.md) remain the evidence for the
17-file, 69.398 GB Backstroke selection. First foreground hashing remained
about 90 seconds; there is no established raw hashing speedup. Background
preparation took 107.04 seconds including the 15-second stability delay.
Subsequent cached grant creation had a 35 ms median with 1,920 bytes read per
request; restarted creation had a 4 ms median and at most 34,688 bytes read.
These are measured cache-reuse results, not guaranteed production latency. This
full audit adds tenant independence, removes repeated claim queries, and moves
source metadata I/O outside the catalog lock; no throughput number is claimed
for those changes.

All installations require signing in again. With `sub`, re-provision SCIM users
when provisioning is required, restore SCIM group roles where used, and update
explicit project member IDs. Otherwise OIDC login creates the new principal and
OIDC group claims can supply roles. Pending and retrying legacy workflow jobs
cannot progress and require review and replacement. Previously released links
retain their grant/project authorization and require explicit revocation when
earlier deliveries must be withdrawn. Email/preferred username installations
retain their previous canonical identity convention.

An abandoned browser sign-in in another process retains state ownership until
cancelled or that process exits. Watch flight sidecars remain one per seen
path; if their count becomes material, cleanup must use the same ownership
protocol. The SQLite Store still serializes database work and its candidate
query can scan a tenant's live rows without a stored-path index. A restore
beyond survey bounds requires operator reconciliation; unqualified local
directories retain missing payload records. These ceilings are documented
rather than replaced with new frameworks or speculative infrastructure.

Existing installer signing limitations remain: macOS is ad-hoc signed and
unnotarized, and Windows MSIX is unsigned. Packaged installers are the update
path; publishing them does not update installed desktops. The audit provides
source coverage and reproducible regression checks, not proof that every future
interleaving, provider configuration, or UI state is bug-free.
